# 财务风险评审系统前端实施计划

> **面向 AI 代理的工作者：** 必须使用 `subagent-driven-development` 逐任务实现，并在每个任务后执行独立审查。前端计划与后端计划分开管理，前端不得绕过 OpenAPI 契约自行发明接口。

**目标：** 基于已审核的 14 个页面原型，交付 Vue 3 + TypeScript 前端，并与后端 OpenAPI、权限范围、状态枚举和证据模型一致。

**架构：** 前端只负责页面展示、输入校验、权限入口、请求状态和用户确认；业务规则、风险结论、审批状态变更全部由后端负责。API 客户端由 FastAPI OpenAPI 生成类型，所有状态使用小写机器值映射为中文标签。请求统一注入 `Authorization`、`Idempotency-Key` 和 `X-Request-ID`；耗时任务通过 SSE `progress`/`result` 接收进度和结果。

**技术栈：** Vue 3、TypeScript、Vite、Pinia、Vue Router、OpenAPI TypeScript 类型、Playwright。

---

## 1. 前置输入与边界

前端开始前必须具备：

- 后端 OpenAPI 文档及统一错误结构：`error.code`、`error.message`、`request_id`；
- `05-数据对象文档.md` 中的版本、附件、风险、审批和报告字段；
- `03-页面原型/` 下统一风格 PNG 原型；
- 后端小写状态枚举和权限角色：`applicant`、`approver`、`finance`、`admin`；
- 已确认的接口：审批决定使用 `POST /api/v1/approval-tasks/{task_id}/decision`，报告保留列表接口和版本详情接口。

前端不得：

- 直接调用 PostgreSQL、Redis、MinIO SDK、OCR、LLM、ProviderRegistry 或 ActionRegistry；
- 根据 AI 建议自动提交通过、退回或驳回；
- 把完整附件、身份证号、银行卡号或原文写入浏览器日志；
- 自行改变后端状态机或权限范围。

- [ ] **步骤 1：建立失败检查**

运行 `Set-Location front; npm run type-check`，确认未创建工程时命令失败。

- [ ] **步骤 2：实现工程壳**

配置 Vue 3、TypeScript、Pinia、Vue Router 和 OpenAPI 类型生成命令；API 客户端统一注入 `Authorization`、`Idempotency-Key` 和请求追踪头。

- [ ] **步骤 4：验证并提交**

- [ ] **步骤 3：验证审批边界**

- [ ] **步骤 3：执行最终验收**

运行 `npm run lint; npm run type-check; npm run build; npm run test:e2e`，并核对 14 个页面、OpenAPI 路径、状态映射、权限隐藏和空/错/加载状态。

- [ ] **步骤 4：提交**

提交 `feat(front): complete financial review frontend`，前端联调以《06-开发实施计划.md》任务 9 完成和后端 OpenAPI 固化为前置条件。

## 7. 前端完成判定

- 14 个页面全部有路由、加载态、空态、错误态和权限入口；
- 所有请求来自 FastAPI OpenAPI 类型客户端，并统一携带 `Authorization`、`Idempotency-Key`、`X-Request-ID`；状态值为后端小写枚举；
- 审批决定必须由审批人员主动确认，AI 不得自动触发；
- 费用报销样板链路通过 Playwright；
- 不提交 `.env`、真实附件、日志、构建产物和本地技能目录。
