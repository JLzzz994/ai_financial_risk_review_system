# 财务单据智能风险审核系统：重点审核点清单

> 每一份文档、图表和原型都需要你审核；`【重点审核】` 用于标出该产出物中最需要关注、最可能影响后续开发的内容。普通章节编排、排版和已确认需求的整理仍需审核，但不作为重点决策。

## 1. 审核标识

- `【重点审核】`：会影响产品范围、核心流程、数据模型、AI 结论、安全边界或主操作链路，需要重点确认。
- `【待确认】`：当前材料不足以做出可靠决策，暂不自行定案。
- `【建议】`：基于工程经验提出，除非被采纳，否则不视为需求。
- `【已确认】`：来自 PRD 或你的明确指令，可直接作为下游输入。

### 2.1 已确认重点决策

| 编号 | 已确认结论 | 对后续工作的影响 |
|---|---|---|
| R-01 | 先以费用报销单打通“创建 → 明细 → 附件 → 解析 → 风险分析 → 人工复核 → 审批 → 报告”样板链路，之后再扩展其他 4 类单据；最终范围仍保留 5 类单据。 | 开发顺序调整，目标范围不缩减。 |
| R-02 | 最终通过、退回或驳回结果由审批人员决定，AI 只提供审批辅助信息。 | AI 不得自动替代审批人员改变最终单据状态。 |
| R-03 | 申请人查看本人单据，审批人员查看分配任务，财务人员查看授权组织范围，管理员主要管理系统配置。 | 后续权限设计必须遵循最小权限原则。 |
| R-04 | 退回后重新提交时，审批流程从第一个审批节点重新开始；旧审批任务取消并保留历史记录。 | 状态机和审批任务设计必须保持版本与历史可追溯。 |
| R-05 | MVP 先实现顺序多节点审批，保留 `approval_mode` 扩展位；会签、或签、转交、加签和代理审批后续再评估。 | 审批模块先保证顺序审批链路，复杂模式不进入当前实现。 |
| R-06 | 金额使用 `Decimal` 保存 2 位小数，保留币种字段；MVP 只比较同币种金额，不做汇率换算。 | 金额字段、金额规则、风险报告和测试用例必须统一口径。 |
| R-07 | 以确定性规则引擎为风险判定主路径，LLM 仅做字段补全、解释和建议。 | 风险规则、综合评级和 AI 设计必须可复现、可审计。 |
| R-08 | 每个风险结论绑定完整证据；缺证据只能标记为待人工确认。 | OCR、风险页面、报告和审计必须保留证据链。 |
| R-09 | OCR、结构化抽取、规则引擎、LLM、Agent、RAG 按职责边界协作，Agent 不得自主改变业务状态。 | AI 技术设计必须实现限权调用和调用链审计。 |
| R-10 | 真实财务数据默认只进入私有化服务；外部模型默认禁止，确需外发时必须脱敏、授权、加密并审计。 | 安全、部署和模型适配层必须实现数据出域控制。 |
| R-11 | 各阶段独立管理任务状态和重试，从失败节点恢复；不可恢复时转人工处理。 | 任务状态机和 SPEC 必须支持幂等、重试和人工接管。 |
| R-12 | 每次提交或退回重提生成不可变版本，相关附件、解析、分析、审批和报告全部绑定版本。 | ER 图、数据对象和报告设计必须禁止串版本。 |
| R-13 | 一期优先完成费用报销单主链路页面，其他 4 类单据复用页面框架。 | 页面原型和前端 SPEC 先保证样板链路闭环。 |
| R-14 | 先建立量化验收指标框架，再用真实或脱敏样本补齐数值。 | 测试验收不得使用未经样本验证的固定目标值。 |
| R-15 | 技术基线为 Python 3.12+、FastAPI、PostgreSQL、Redis + Celery、Vue 3 + TypeScript 和 OpenAPI；OCR 与模型服务通过独立适配层接入。 | 概要设计、模块 SPEC 和部署方案按此基线展开。 |
| R-16 | 附件存储采用 `FileStorage` 接口抽象；开发环境使用本地文件存储，生产环境使用 MinIO 对象存储。 | 附件模块不直接依赖具体存储实现，生产部署需要配置 MinIO。 |
| R-17 | OCR/模型服务优先采用私有化部署；外部模型只处理脱敏或明确获准的数据。 | 架构必须保留模型适配层、数据出域控制和调用审计。 |

## 4. 后续产出中的标记方式

### 4.1 概要设计总纲

只在以下内容旁标注 `【重点审核】`：

- 总体架构和模块边界；
- 文件存储、任务队列、OCR、规则引擎、LLM/Agent/RAG 的组合方式；
- 数据权限、版本快照、审计和失败恢复的总体策略；
- 性能、安全、数据出域和部署边界。

普通的模块说明、目录排版和已确认 PRD 内容不标重点。

### 4.2 架构图、流程图、状态机和 ER 图

只标注会改变实现方向的关系：

- `【重点审核】` 模块之间的调用方向和异步边界；
- `【重点审核】` 单据、审批、解析、分析和报告的状态转换；
- `【重点审核】` 单据版本与附件、风险结果、审批实例和报告的关联；
- `【待确认】` 尚未决定的外部系统或数据来源。

图中的普通节点名称不要求逐项审核。

### 4.3 OCR、LLM、Agent、RAG 技术设计

只标注这些关键点：

- `【重点审核】` OCR 识别与规则计算的职责边界；
- `【重点审核】` LLM 是否参与风险判定，还是只做分类、解释和建议；
- `【重点审核】` Agent 可调用的工具、权限范围和审计链路；
- `【重点审核】` RAG 的数据源、时效、切分、检索和越权防护；
- `【重点审核】` 低置信度、字段冲突、模型超时和人工复核处理；
- `【待确认】` 模型部署方式、版本、真实数据出域和评估指标。

### 4.4 页面原型

只标注关键交互：

- `【重点审核】` 单据创建、提交、退回重提和审批操作；
- `【重点审核】` 附件原文与结构化字段的证据定位；
- `【重点审核】` 金额核对和风险项人工确认；
- `【重点审核】` 无权限、失败、重试、只读和低置信度状态；
- `【待确认】` 视觉风格、布局细节和非核心页面装饰。

当前没有可直接调用的 `pen.dev` 工具，页面先交付可复刻的原型规格；取得连接后再补充 `.pen` 文件。
