# 接口说明

完整机器可读契约见 [`接口/openapi.json`](接口/openapi.json)，运行服务后也可在 `http://127.0.0.1:8000/docs` 查看 Swagger UI。

## 通用约定

- API 前缀：`/api/v1`。
- 登录后使用 `Authorization: Bearer <access_token>`。
- 写操作建议携带 `Idempotency-Key`，提交、分析、审批、报告导出必须使用稳定且唯一的业务幂等键。
- 金额传字符串，例如 `"100.00"`；货币 MVP 只支持 `CNY`。
- 错误返回包含 `request_id`，业务错误使用统一错误结构。

## 1. 登录

```bash
TOKEN=$(curl -fsS -X POST http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo_applicant","password":"Demo123!"}' \
  | jq -r '.access_token')
curl -fsS http://127.0.0.1:8000/api/v1/auth/me \
  -H "Authorization: Bearer $TOKEN"
```

## 2. 单据和版本

创建费用报销草稿：

```bash
curl -fsS -X POST http://127.0.0.1:8000/api/v1/documents \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "applicant_id":"<登录用户的 user_id>",
    "applicant_department":"研发部",
    "total_amount":"1280.00",
    "currency":"CNY",
    "apply_date":"2026-08-18",
    "reason_text":"客户现场差旅费用",
    "line_items":[{
      "expense_item":"交通费",
      "expense_date":"2026-08-17",
      "amount":"1280.00",
      "currency":"CNY",
      "invoice_no":"DEMO-INV-001"
    }]
  }'
```

提交并创建不可变 `document_version`：

```bash
curl -fsS -X POST http://127.0.0.1:8000/api/v1/documents/<document_id>/submit \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-submit-<document_id>-v1' \
  -d '{"reason":"提交审核","expected_state_version":1}'
```

## 3. 附件和 OCR

生产 PostgreSQL 模式上传附件时必须绑定 `document_version_id`：

```bash
curl -fsS -X POST \
  "http://127.0.0.1:8000/api/v1/documents/<document_id>/attachments?document_version_id=<document_version_id>" \
  -H "Authorization: Bearer $TOKEN" \
  -F 'file=@./receipt-demo.txt;type=text/plain'
```

查询附件、解析状态、预览和下载：

```text
GET  /api/v1/documents/{document_id}/attachments
GET  /api/v1/attachments/{attachment_id}/parse-status
POST /api/v1/attachments/{attachment_id}/parse
GET  /api/v1/attachments/{attachment_id}/preview
GET  /api/v1/attachments/{attachment_id}/download
```

文件内容由 `FileStorage` 管理，数据库只保存对象键和元数据。

## 4. 分析和风险复核

异步启动分析：

```bash
ANALYSIS=$(curl -fsS -X POST \
  http://127.0.0.1:8000/api/v1/documents/<document_id>/analysis \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-analysis-<document_version_id>' \
  -d '{"document_version_id":"<document_version_id>"}')
TASK_ID=$(printf '%s' "$ANALYSIS" | jq -r '.task_id')
```

查询状态、风险项和 SSE 事件：

```text
GET /api/v1/analysis-tasks/{task_id}
GET /api/v1/analysis-tasks/{task_id}/findings
GET /api/v1/analysis-tasks/{task_id}/events?last_event_id=0
```

规则引擎负责确定性风险判断；风险证据不足时只能进入人工确认，不能自动改变审批状态。

## 5. 顺序审批

审批人查询分配任务：

```text
GET /api/v1/approval-tasks?task_status=pending
GET /api/v1/approval-tasks/{task_id}
```

提交第一节点决定：

```bash
curl -fsS -X POST http://127.0.0.1:8000/api/v1/approval-tasks/<task_id>/decision \
  -H "Authorization: Bearer <approver_token>" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-decision-<task_id>-approve' \
  -d '{"decision":"approve","review_comment":"证据完整，部门审批通过"}'
```

第二节点由财务账号重复查询并审批。支持 `approve`、`return`、`reject`；退回会创建新版本并保留旧任务、意见和审计历史。

## 6. 报告和审计

```text
GET  /api/v1/review-reports/{document_version_id}
POST /api/v1/review-reports/{document_version_id}/finalize
POST /api/v1/review-reports/{document_version_id}/export
GET  /api/v1/review-reports/exports/{export_task_id}
GET  /api/v1/review-reports/exports/{export_task_id}/download
GET  /api/v1/documents/{document_id}/approval-history
GET  /api/v1/audit-logs
```

报告必须绑定不可变 `document_version_id`；审批决定、人工复核、模型调用和敏感下载都会写入审计日志。
