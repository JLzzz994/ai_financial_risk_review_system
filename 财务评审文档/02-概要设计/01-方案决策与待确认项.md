# 财务单据智能风险审核系统：方案决策与待确认项

> 状态：关键决策已完成确认，进入概要设计编制。本文档与 PRD、重点审核门禁清单共同作为后续设计输入。
>
> 审核规则：每个产出物都需要整体审核；标记为“【重点审核】”的内容是需要优先检查的关键约束。

| R-09 | OCR 负责识别，结构化抽取负责字段，规则引擎负责校验，LLM 负责补全/解释/建议，Agent 只编排，RAG 只检索制度和规则依据。 | 组件权限和调用链固定，Agent 不得自主改变业务状态。 |
| R-10 | 真实财务数据默认只进入私有化服务；外部模型默认禁止，确需外发时必须脱敏、授权、加密并审计。 | 实现数据出域控制、访问控制、留存策略和调用审计。 |
| R-11 | 上传、解析、OCR、分析、报告分别管理状态和重试；从失败节点恢复，保留错误、日志和幂等键；不可恢复时转人工。 | 任务状态机支持幂等、局部重试和人工接管。 |
| R-12 | 每次提交或退回重提生成不可变版本；附件、解析、分析、审批和报告全部绑定同一版本。 | 新规则/模型只影响新分析，历史结果不可改写。 |
| R-13 | 一期优先完成费用报销单页面主链路，其他单据复用页面框架。 | 原型和前端 SPEC 先保证样板链路闭环。 |

| R-16 | `FileStorage` 接口抽象；开发环境本地文件存储，生产环境 MinIO 对象存储。 | 业务模块不直接依赖具体存储实现。 |
| R-17 | OCR/模型服务优先私有化；外部模型只处理脱敏或明确获准的数据。 | 模型适配层必须支持出域策略、脱敏和审计。 |
| R-18 | 审批执行引擎固定为顺序状态机；管理员可以按单据类型、金额区间、组织和角色配置审批流程模板。模板发布后版本不可变，已创建实例继续使用创建时绑定的模板版本。 | 执行器只执行 `sequential` 模式，不允许 Agent、YAML 或 LangGraph 动态增删、跳过、重排节点；流程配置模块负责模板草稿、发布、停用和版本管理。 |

| R-22 | 认证采用短期 JWT + Redis 撤销；Token 默认有效期 30 分钟，MVP 暂不提供 Refresh Token；密码优先 Argon2id，兼容 bcrypt；Redis 不可用时认证失败关闭。 | 不新增 Token 持久化表；登录失败限流使用 Redis；禁用用户通过每次请求的用户状态检查立即失效。 |

| R-24 | 登录失败限流同时按账号和 IP 计数，任一维度触发阈值即拒绝；不向客户端暴露具体限流维度。 | Redis 保存短期计数和锁定状态，认证接口统一返回 `INVALID_CREDENTIALS` 或认证依赖不可用。 |
| R-25 | 权限目录由系统内置并通过数据库迁移维护，管理员只能查看和分配权限，不能在运行时创建或删除权限。 | 权限码必须版本化；角色权限变更递增关联用户的 `permission_version`。 |
| R-26 | 权限范围以《财务风险评审项目说明.md》为准，满足登录、角色授权、数据权限、用户/角色/权限维护和审计要求，不额外扩展权限模型。 | 认证模块保持最小可用边界，后续业务模块只声明实际需要的权限码。 |
| R-27 | 会话意图和槽位置信度采用两级默认阈值：`>=0.75` 允许继续，`0.50`～`<0.75` 要求确认，`<0.50` 重新询问或转人工。 | 阈值由系统参数管理，Agent 不能运行时修改。 |
| R-28 | 操作审计日志至少保留 3 年；到期后归档，不直接物理删除。 | 登录、权限拒绝、附件访问、规则变更、分析、复核、审批和报告导出均纳入审计。 |
| R-29 | 源说明书中的兼容接口必须与规范接口共享同一应用服务和事实来源。 | 文档/路由层可保留历史路径，但不得形成第二套状态机、报告生成或审批写入逻辑；以规范接口和版本绑定数据为权威。 |

## 1.1 统一技术基线与术语边界

为避免概要设计、SPEC 和实现阶段出现多套说法，统一采用以下术语：

- `ProviderRegistry`：外部能力适配器注册中心。
- `ActionRegistry`：Agent 可调用的业务动作注册中心。
- `ReviewSession` / `ReviewTurn`：审核交互上下文及单轮交互记录。
- `Settings`：环境配置统一出口。
- `Unit of Work`：事务边界，协调独立 `AsyncSession` 的提交与回滚。

统一分层契约如下：

```text
Router -> Service/UoW -> Repository/Adapter
```

- API Schema 与 ORM 分离，Service 不拼接 SQL。
- 业务代码不得直接导入 MinIO、OpenAI 或 OCR SDK；外部能力必须经 Adapter 和 `ProviderRegistry` 接入。
- Agent 只能经 `ActionRegistry` 调用白名单动作。
- 每个请求或任务使用独立 `AsyncSession`，配置只从 `app.config.settings` 获取。

统一事实源与禁止事项如下：

- PostgreSQL 保存业务事实、版本、审计和阶段状态；Redis 只用于 broker、短期缓存、撤销、限流和锁。
- `document_version_id` 是附件、风险、审批和报告的绑定主线。
- 审批决定只能通过统一 `decision` 服务进入固定顺序状态机。
- 禁止动态 YAML 或 `eval` 改审批节点。
- 禁止 LLM 或 Agent 直接改变审批状态。
- 禁止 Redis 作为业务事实源、会话状态覆盖 `document_version` 历史，或同步 API 执行 OCR、分析和报告长任务。


以下内容不改变已确认方向，但需要在对应产出物中给出可执行定义：

| 项目 | 细化内容 | 产出物 |
|---|---|---|
| 风险评级参数 | 高/中/低的具体阈值、数量修正、无风险等级、已排除风险是否参与汇总 | 风险规则设计、验收标准 |
| 证据数据结构 | 页码、坐标、文本片段、字段路径、置信度和规则/模型版本的字段定义 | 数据对象文档、模块 SPEC |
| 任务参数 | 最大重试次数、退避策略、超时、幂等键生成和人工接管权限 | 概要设计、任务 SPEC |
| 安全参数 | 脱敏字段清单、外发审批、密钥管理、日志留存和数据保留期限 | 安全设计、部署方案 |
| 验收数值 | 样本集、统计口径、准确率、完整率、耗时和容量目标 | 测试验收方案 |
| 页面细节 | 费用报销单字段布局、风险证据联动、审批操作和报告导出交互 | 页面原型、前端 SPEC |
