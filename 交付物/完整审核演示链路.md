# 完整审核演示链路

下面链路使用脱敏示例数据，目标是演示“申请人提交 → OCR/附件 → 异步分析 → 风险人工复核 → 两节点顺序审批 → 报告固化 → 审计追溯”。

## 0. 启动和准备

```powershell
.\交付物\启动.ps1 -SeedDemo
.\交付物\检查.ps1
```

打开 `http://127.0.0.1:5173/`，使用 `demo_applicant / Demo123!` 登录。

## 1. 申请人创建和提交

1. 进入“我的单据”，创建费用报销单。
2. 填写单据日期、部门、事由、金额和费用明细；明细合计必须等于总金额。
3. 上传脱敏附件，确认附件状态为 `stored`。
4. 点击“提交审核”，系统创建不可变 `document_version`，单据进入 `pending_review`。
5. 记录页面展示的 `document_id`、`document_version_id` 和分析任务 ID。

验收点：草稿可编辑；提交后版本号递增；旧版本不可被覆盖；附件绑定到同一 `document_version_id`。

## 2. 分析流水线

1. 前端触发 `POST /api/v1/documents/{document_id}/analysis`。
2. API 立即返回 `202` 和 `task_id`，不在 API 进程执行 OCR/规则/报告长任务。
3. Worker 依次推进 `queued → parsing → extracting → analyzing → aggregating → succeeded`。
4. 页面通过 SSE `/api/v1/analysis-tasks/{task_id}/events` 展示进度，也可刷新后用状态接口恢复。
5. 在风险列表查看风险级别、规则版本、证据片段和定位信息。

验收点：Redis 只承载队列和短期状态；分析事实、重试次数、错误和人工接管状态写入 PostgreSQL。

## 3. 人工复核

1. 退出申请人账号，使用 `demo_approver / Demo123!` 登录。
2. 进入工作台，打开刚提交的单据和风险项。
3. 对证据不足或命中规则的风险项填写处理意见，提交 `review-status`。
4. 人工复核只改变风险项复核状态，不直接改变审批状态。

验收点：复核人必须是当前授权用户；意见不能为空；证据和复核时间可追溯。

## 4. 第一审批节点

1. 使用审批人账号查看“审批任务”，确认任务节点为“部门审批”。
2. 检查单据金额、附件、风险证据和分析结论。
3. 选择“通过”并填写意见；前端使用 `Idempotency-Key` 防止重复提交。
4. 审批通过后，固定顺序状态机创建第二节点“财务复核”；不能跳过节点。

验收点：AI 只能提供辅助结果；最终决定由审批人员通过统一 decision 服务提交。

## 5. 第二审批节点和报告

1. 使用 `demo_finance / Demo123!` 登录。
2. 在审批任务中打开同一单据，复核金额、风险和附件。
3. 提交第二节点“通过”，单据进入最终通过状态。
4. 打开报告中心，查看绑定当前版本的报告。
5. 由授权人员固化报告；需要文件时创建 PDF/XLSX 异步导出任务并轮询状态。

验收点：报告、审批历史和附件均绑定同一版本；退回重提会生成新版本，旧任务和意见保留。

## 6. 审计追溯

使用管理员或授权财务账号查看审计日志，检查以下事件：

- 登录、退出和权限拒绝；
- 上传、解析、预览和下载附件；
- OCR/模型调用与分析重试；
- 风险人工复核；
- 每个审批节点的决定和意见；
- 报告固化和导出。

## 7. 退回分支（可选）

在第一审批节点选择 `return` 并填写退回原因：

1. 申请人收到退回意见并修改草稿。
2. 重新提交创建新 `document_version`。
3. 新版本从第一个审批节点重新开始。
4. 旧版本、旧任务、风险和意见保持只读历史。

## 8. 失败和人工接管

停止 Worker 后触发一次分析，页面应看到任务停留或失败；恢复 Worker 后可通过重试接口继续。超过自动重试上限时，任务进入 `manual_takeover`，由人工接管，不得静默生成通过结论。
