# 财务单据智能风险审核系统数据对象文档

> 版本：V0.1
>
> 依据：`财务评审文档/财务风险评审项目说明.md` 第 2.7.10 节、PRD、已审核通过的概要设计总纲及 R-03、R-06、R-08、R-12 决策。
>
> 数据库：PostgreSQL。金额使用 `NUMERIC(18,2)`，业务代码使用 Python `Decimal`。
>
> 审核说明：本文档需要整体审核；标记“【重点审核】”的字段、约束和关系优先审核。

## 1. 设计约定

### 1.1 通用字段

除关联表和纯明细表外，业务表默认包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键，应用层生成或数据库生成 |
| `created_at` | TIMESTAMPTZ | 创建时间，UTC 保存 |
| `updated_at` | TIMESTAMPTZ | 最近更新时间；不可变历史表可不设置 |

### 1.2 类型约定

| 业务含义 | PostgreSQL 类型 | 约定 |
|---|---|---|
| 金额 | `NUMERIC(18,2)` | 不使用浮点数；同一比较组必须币种一致 |
| 长文本/原文 | `TEXT` | 不限制业务长度；接口层单独限制 |
| 状态/编码 | `VARCHAR(32)` 或 `VARCHAR(64)` | 使用小写英文枚举值 |
| 扩展字段 | `JSONB` | 只保存结构化扩展，不替代核心查询字段 |
| 时间 | `TIMESTAMPTZ` | 接口统一 ISO 8601，数据库统一 UTC |
| 文件大小 | `BIGINT` | 单位：字节 |
| 置信度 | `NUMERIC(5,4)` | 范围 `0.0000`～`1.0000` |

### 1.3 核心版本规则

【重点审核 R-12】首次提交和每次退回重提生成一条 `document_versions`。附件、解析结果、分析任务、风险项、审批实例、人工复核和报告必须通过 `document_version_id` 绑定到同一版本。新规则或模型不得改写历史结果。

### 1.4 权限规则

【重点审核 R-03】

- 申请人：只能访问本人创建的单据和版本；
- 审批人员：只能访问分配给本人的审批任务及其绑定单据；
- 财务人员：按授权组织范围访问单据、规则、市场价和供应商资料；
- 系统管理员：管理用户、角色、权限、流程和系统参数，业务数据仍需单独授权。

## 13. 重点审核清单

- 【重点审核 R-03】数据权限是否能落到字段和查询条件，而不是只停留在角色名称。
- 【重点审核 R-06】金额是否全部使用 `NUMERIC(18,2)`、`Decimal` 和币种字段；是否禁止 MVP 隐式汇率换算。
- 【重点审核 R-08】风险项是否能定位到附件、页码/位置、原文片段、字段、置信度、规则版本和分析时间。
- 【重点审核 R-12】附件、解析、分析、风险、审批和报告是否全部绑定 `document_version_id`。
- 【重点审核 R-16】附件表是否只保存 FileStorage 对象键，是否避免直接暴露文件路径。
