# Python 数据对象设计 Skill

## 输入优先级

1. 用户当前指令、PRD 和已确认决策。
2. 概要设计、原型和模块 SPEC。
3. 现有 Alembic 迁移、SQLAlchemy 模型、API schema 和页面字段。

发现冲突时列出冲突、采用依据和待确认项；关键规则未知时不得猜测。

## 工作流

1. 确定对象中文名、表名、模块、数据主责、生命周期、存储位置和删除方式。
2. 区分持久化字段、查询聚合字段和外部对象存储元数据；明确“不保存什么”。
3. 为每个字段给出数据库字段名、Python 类型、PostgreSQL 类型、必填、默认值、含义、精度、枚举和约束。
4. 检查主键、审计字段、逻辑删除、版本绑定、权限过滤、证据链、幂等键和 JSONB 扩展字段。
5. 与项目已有表结构、迁移和命名规范逐项对齐。

## 类型与建模约束

| 业务含义 | Python 类型 | PostgreSQL 类型 |
|---|---|---|
| 主键/关联标识 | `UUID` | `UUID` |
| 金额 | `Decimal` | `NUMERIC(18,2)` |
| 百分比/高精度数值 | `Decimal` | `NUMERIC(18,6)` |
| 时间 | `datetime` | `TIMESTAMPTZ` |
| 状态/枚举 | `Enum` 或 `str` | `VARCHAR` |
| 灵活扩展字段 | `dict[str, Any]` | `JSONB` |
| 文件大小/计数 | `int` | `BIGINT` 或 `INTEGER` |

- 不使用浮点数保存金额；明确舍入方式和币种。
- 版本绑定和证据链字段按项目需求定义，不默认引入具体业务字段。
- 默认使用逻辑删除；如果对象不可删除或必须保留历史，明确说明。
- 外键和索引只有在需求、概要设计或 SPEC 中有依据时才加入；不要静默引入级联删除。
- 查询聚合字段必须写明统计范围、版本过滤、逻辑删除过滤、无数据返回值及是否持久化。

## 输出结构

1. 文档说明与依据
2. 对象职责与边界
3. 表目录
4. 字段明细（表名、字段名、Python 类型、PostgreSQL 类型、必填、默认值、约束、说明）
5. 对象关系与版本绑定
6. 状态枚举与生命周期
7. 索引/查询建议及其依据
8. 待确认项与重点审核项

默认保存到用户指定的设计文档目录。不要输出建表 SQL、Python 实现代码、接口清单或页面设计。

## 评审清单

- 表名是否与项目说明一致，字段是否能支撑页面、接口和流程。
- 权限是否能落到查询条件。
- 金额、时间、枚举、版本和证据是否符合项目约束。
- 存储、审计、删除和数据保留策略是否有依据。
