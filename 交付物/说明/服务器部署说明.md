# 服务器部署说明

本部署包只包含源码、迁移、配置模板和 `requirements.txt`，不包含 Python 虚拟环境、`site-packages`、Node 依赖、上传文件或日志。服务器需要能够访问镜像仓库和 Python/npm 包源，依赖在构建或安装阶段获取。

## 1. 服务器准备

建议使用 Linux x86_64、Python 3.11+、Docker Engine 24+ 和 Docker Compose v2.24+。将 `financial-review-server-*.zip` 上传后解压：

```bash
unzip financial-review-server-*.zip
cd financial-review
cp .env.example .env
```

编辑 `.env`，至少修改以下生产配置：

```dotenv
ENVIRONMENT=production
DOCUMENT_BACKEND=postgres
AUTH_BACKEND=postgres
POSTGRES_USER=app
POSTGRES_PASSWORD=请生成随机强密码
JWT_SECRET=请生成至少32字节随机字符串
MINIO_ACCESS_KEY=请生成随机账号
MINIO_SECRET_KEY=请生成随机强密码
MILVUS_MINIO_ACCESS_KEY=请生成随机账号
MILVUS_MINIO_SECRET_KEY=请生成随机强密码
# 启用 RAG 时再填写外部模型服务
RAG_ENABLED=false
RAG_EMBEDDING_BASE_URL=
RAG_RERANKER_ENABLED=false
RAG_RERANKER_BASE_URL=
```

不要把 `.env` 提交到代码仓库，也不要把真实财务文件放入部署包。

## 2. 校验和启动

以下命令使用服务器部署覆盖配置：内部服务不暴露宿主机端口，仅 API 暴露 `8000`。首次启动先启动 PostgreSQL、Redis、MinIO、Milvus（含 etcd/专用 MinIO），再执行迁移，最后启动 API 和 Celery worker。BGE-M3/Reranker 不在服务器 Compose 中运行。

```bash
COMPOSE="docker compose -f docker-compose.yml -f docker-compose.app.yml -f docker-compose.server.yml"

$COMPOSE config
$COMPOSE up -d postgres redis minio milvus-etcd milvus-minio milvus
$COMPOSE run --rm --no-deps api uv run alembic upgrade head
INSTALL_RAG_DEPS=true $COMPOSE build api worker
$COMPOSE up -d api worker

curl http://127.0.0.1:8000/health/live
curl http://127.0.0.1:8000/health/ready
```

如果前面有 Nginx/Caddy，反向代理到 `127.0.0.1:8000`，并由代理负责 HTTPS、域名和上传大小限制。

### 已有基础设施时（本服务器适用）

如果服务器已经由另一个 Compose 项目运行 PostgreSQL、Redis、MinIO，不要再启动它们。本项目仍负责 Milvus（含 etcd/专用 MinIO），使用复用现有网络的覆盖文件：

```bash
INFRA_ENV_FILE=/root/risk/.env
INFRA_NETWORK_NAME=risk_app-network
COMPOSE="docker compose --env-file /root/risk/.env -f docker-compose.app.yml -f docker-compose.server-existing-infra.yml"

$COMPOSE config
$COMPOSE run --rm --no-deps api uv run alembic upgrade head
$COMPOSE build api worker
$COMPOSE up -d api worker
```

该方式创建 API、worker 和本项目的 Milvus 三件套，复用 `/root/risk/.env` 中的数据库、Redis 和 MinIO 配置。停止时只操作本项目容器：

```bash
$COMPOSE stop api worker milvus milvus-etcd milvus-minio
```

## 3. 前端构建与部署

推荐在本地构建前端，服务器不需要安装 Node.js。Windows PowerShell 执行：

```bash
cd front
npm ci
npm run build
cd ..
./deploy/package_frontend.ps1
```

将生成的 `financial-review-frontend-*.zip` 上传到服务器并解压到：

```text
/opt/financial-review/frontend-dist
```

当前服务器的 `run_service.sh` 已将该目录挂载到 FastAPI 根路径，并自动提供 Vue history 路由回退；`/api/` 请求仍由同一个 API 进程处理。因此浏览器访问根路径即可打开前端，不需要额外安装 Nginx 或 Node.js。

如果通过 SSH 隧道访问，在本地执行：

```powershell
ssh -N -L 18000:127.0.0.1:8000 root@121.40.148.74
```

然后打开 `http://127.0.0.1:18000/`；API 文档为 `http://127.0.0.1:18000/docs`。

生产构建必须保持 `VITE_API_BASE_URL=/api/v1` 和 `VITE_ENABLE_MOCK=false`，这样前端与后端使用同源请求。

## 4. 查看、停止和更新

```bash
# 查看状态和日志
$COMPOSE ps
$COMPOSE logs -f api worker

# 停止容器，保留数据卷
$COMPOSE stop

# 删除容器和网络，保留数据卷
$COMPOSE down

# 发布新版本：上传新包后执行
$COMPOSE up -d --build api worker
$COMPOSE run --rm --no-deps api uv run alembic upgrade head
```

`down -v` 会删除本项目定义的 PostgreSQL、Redis、MinIO 和 Milvus 数据卷，只能在确认已备份且确实要清空数据时执行。复用现有基础设施模式下，外部项目的数据卷不由本项目 Compose 管理。

## 5. 数据备份与恢复

```bash
# PostgreSQL 逻辑备份
$COMPOSE exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup-$(date +%F).sql

# 恢复前先停止 API/worker；以下命令会覆盖目标库中的同名对象
cat backup-2026-01-01.sql | $COMPOSE exec -T postgres psql -U "$POSTGRES_USER" "$POSTGRES_DB"
```

MinIO 数据位于 `minio_data` 卷，Milvus 数据位于 `milvus_data`、`milvus_etcd_data` 和 `milvus_minio_data` 卷，需要按服务器存储策略做快照/备份。Redis 仅用于队列和短期状态，不是业务事实源。

## 6. 非 Docker 方式（可选）

若服务器不使用应用容器，可使用清单安装运行时依赖；依赖不会随部署包携带：

```bash
uv venv --python 3.11 --clear .venv
. .venv/bin/activate
python --version  # 必须显示 Python 3.11.x
uv sync --python 3.11 --frozen --no-dev

alembic upgrade head
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 另一个进程启动 worker
celery -A app.tasks.celery_app worker --loglevel=INFO
```

服务器上可直接安装部署包提供的 systemd 服务，使 API 和 worker 随系统启动：

```bash
install -m 0755 deploy/run_service.sh /opt/financial-review/run_service.sh
install -m 0644 deploy/systemd/*.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now financial-review-api financial-review-worker
systemctl status financial-review-api financial-review-worker
```

查看日志和关闭服务：

```bash
journalctl -u financial-review-api -u financial-review-worker -f
systemctl stop financial-review-api financial-review-worker
```

非 Docker 部署必须自行提供 PostgreSQL、Redis、MinIO、Milvus、OCR 以及外部 BGE-M3/Reranker 服务，并在 `.env` 中填写可访问地址。生产环境不要运行 `seed_demo_data.py`；该脚本仅用于本地演示数据。

如果已有 `.venv` 是 Python 3.12，必须使用 `uv venv --python 3.11 --clear .venv` 重建，不能在原环境上继续 `uv sync`。
