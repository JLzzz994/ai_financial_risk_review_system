## 1. 系统总体架构图

【重点审核 R-15、R-16、R-17：技术栈、MinIO、OCR/模型适配层及数据出域边界。】

```mermaid
flowchart TB

    end
    API --> AUTH & DOC & FILE & WF & RISK & REPORT

    DOC & AUTH & WF & RISK & REPORT --> PG[(PostgreSQL)]
    FILE --> FS[FileStorage 接口]
    FS --> LOCAL[(开发：本地文件)]
    FS --> MINIO[(生产：MinIO)]

    API --> REDIS[(Redis)]

    CELERY --> LLM[LLM Adapter]
    CELERY --> RAG[RAG 检索]
    OCR & LLM & RAG --> AUDIT[调用审计/证据记录]
    AUDIT --> PG
```

## 2. 费用报销单样板链路

【重点审核 R-01、R-02、R-04、R-08、R-11、R-12：样板范围、人工审批、退回重提、证据、重试和版本绑定。】

```mermaid
flowchart LR
    A([创建费用报销单]) --> B[填写明细与金额]
    B --> C[上传 PDF/PNG/JPG 附件]
    C --> D{格式/权限校验}
    D -- 不通过 --> C
    D -- 通过 --> E[提交并生成不可变版本]
    E --> F[异步 OCR/字段提取]
    F --> G{解析成功?}
    G -- 否 --> H[记录错误并从失败节点重试]
    H --> F
    G -- 是 --> I[规则引擎执行十类风险检查]
    I --> J[绑定证据并生成风险项]
    J --> K[人工复核风险项]
    K --> L{审批人员决定}
    L -- 退回 --> M[修改后重新提交并生成新版本]
    M --> E
    L -- 驳回 --> N([驳回])
    L -- 通过 --> O[生成版本绑定报告]
    O --> P([报告导出/审计追溯])
```

## 3. 单据状态机

【重点审核 R-04、R-05：退回后从首节点重新开始，MVP 仅顺序审批。】

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已提交 : 提交
    已提交 --> 解析中 : 创建版本/投递任务
    解析中 --> 待复核 : 解析成功
    解析中 --> 解析失败 : 解析异常
    解析失败 --> 解析中 : 有权限用户重试
    待复核 --> 审批中 : 风险复核完成
    审批中 --> 审批中 : 顺序节点通过
    审批中 --> 退回 : 审批人员退回
    退回 --> 已提交 : 修改后重新提交/新版本
    审批中 --> 驳回 : 审批人员驳回
    审批中 --> 已通过 : 最终节点通过
    草稿 --> 已作废 : 作废
    退回 --> 已作废 : 作废
```

## 5. 审核顺序

1. 先审核总体架构是否符合模块化单体和既定技术栈。
2. 再审核费用报销单样板链路是否完整闭环。
3. 再审核退回、重试、人工审批和版本绑定。
4. 最后审核数据对象的金额、证据、权限字段。
